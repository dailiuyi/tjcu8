# CSS 架构

所有页面继续只引用 `css/style.css`。这个文件是稳定入口，仅按以下顺序导入职责模块：

1. `base.css`：文档基础、固定背景和通用工具类。
2. `layout.css`：页头、导航、内容区和页脚。
3. `components.css`：卡片、诗歌、图集和正文组件。
4. `pages.css`：图片索引与服务页专属组件。
5. `responsive.css`：减少动态效果和 768px 移动端覆盖。

这类似 Spring 配置入口按依赖顺序装配多个职责单一的模块。基础规则先加载，响应式覆盖最后加载；页面无需知道内部拆成了多少文件。

新增全站组件样式时放入 `components.css`，只服务单个页面时放入 `pages.css`。不要在职责文件中继续使用 `@import`，也不要绕过入口让某个 HTML 单独加载模块。修改后运行 `python scripts/check-site.py`，检查器会验证模块名称、顺序及禁止嵌套导入的约束。
